# Layers and chive records for the dataset

This directory holds **22,938** ATProto records that release the dataset of
White, Grimm, & Glass (2026), *Aspect is not a fixed property of linguistic
expressions* (ELM 4), on [Layers](https://layers.pub) (`pub.layers.*`: the
stimuli, annotations, experiments, participants, trial-level judgments, and
derived measures) and describe the paper on [chive](https://chive.pub)
(`pub.chive.*`). Every record is generated by `scripts/generate_metadata.py`
from the tracked files in `data/`, `materials/experiment_text.json`, `paper/`,
and `metadata/cache/`, and is checked by `scripts/check_metadata.py`.

All records are generated in one new account on factslab.io. Its DID is the single
configuration value, `account` in `release.toml`. Only the Layers records are
published from that account; the chive records in `chive/` are for the first
author to submit from their personal account (see *Publishing*). Until that account exists, the
value is a syntactically valid placeholder (`did:plc:placeholderfactslabioaaa`)
that resolves to nothing. Nothing has been published.

| Component | Version |
|---|---|
| Layers lexicons | **0.11.0** (layers `v0.11.0`, git `da20595`), as vendored by lairs |
| lairs | **0.9.0** (PyPI), with the dependency pins of its own `v0.9.0` lockfile (`requirements.lock`) |
| `@atproto/lexicon` (strict validator) | **0.7.19** (`package.json`, `package-lock.json`) |
| chive lexicons | `~/chive/lexicons`, git `cc4f2f45` |
| PropBank / VerbNet in the Layers repository | the commits pinned in `cache/lexical_refs.json` |

The working copy of `~/Projects/layers-pub/layers` (branch `feat/appview`) lags
`v0.11.0` in `judgment/defs.json` (it lacks `continuousValue`). The records
therefore target the tagged 0.11.0 tree that lairs vendors, not that checkout.

## Reproduce

```bash
cd metadata
uv venv --python 3.14 .venv && uv pip install --python .venv/bin/python -r requirements.lock
npm ci                                                # the strict validator
.venv/bin/python scripts/resolve_lexical_refs.py      # optional: re-pin PropBank/VerbNet (network)
Rscript scripts/export_fits.R                         # optional: needs analysis/fits/*.rds (~1.1 GB)
.venv/bin/python scripts/generate_metadata.py         # writes layers/ and chive/
.venv/bin/python scripts/check_metadata.py --live     # everything below; --live re-fetches targets
```

Generation needs no network and no R: it reads the committed caches. The two
optional steps rebuild those caches. `export_fits.R` reads the fits that
`analysis/reproduce.ipynb` writes and reproduces the paper's numbers
(for instance β = 1.71 [1.21, 2.24] for verb type in §2.5 and the match
values .79, .10, and .21 in §4).

Expected check output (abridged):

```
1. pins            lairs 0.9.0 / Layers 0.11.0 / libipld 3.4.1 / @atproto/lexicon 0.7.19
2. lairs           22888/22888 pub.layers records decode into lairs models
3. strict          22938/22938 records valid against Layers 0.11.0 (114 docs) + chive (243 docs)
4. references      112685 in-account references, all resolve to generated records
                   12673 references into PropBank/VerbNet (4750 distinct records), all pinned
                   live: 4750/4750 fetched from repo.layers.pub with lairs; 4750/4750 CIDs unchanged
5. fidelity        every row and column of the three trial CSVs, the inventory (apart from
                   its unreported columns), the verb list, and the OntoNotes distribution
                   is reproduced from the records
6. determinism     regeneration is byte-identical
```

## Scripts

| Script | Does |
|---|---|
| `scripts/resolve_lexical_refs.py` | Resolves the five PropBank/VerbNet accounts with lairs, downloads each repository once (`PdsClient.get_repo_car`, `decode_repo_car`), and writes `cache/lexical_refs.json`: every roleset, lemma entry, VerbNet member, and VerbNet class the release points to, with its DID-based AT-URI, its CID, and the repository commit it was read from. |
| `scripts/export_fits.R` | Reads the three brms fits and the §4 caches; writes `cache/sentence_measures.csv`, `pair_measures.csv`, `fit_parameters.csv`, `sense_proportions.csv`, `sense_weights.csv`. |
| `scripts/generate_metadata.py` | Builds every record and validates each against its lairs model before writing it. |
| `scripts/validate_lexicons.mjs` | Strict validation with `@atproto/lexicon`: formats, lengths, required fields, ranges, blobs, record keys. |
| `scripts/check_metadata.py` | Steps 1 to 6 above; exits non-zero on any failure. |
| `scripts/publish.py` | Plans (default) or applies (`--yes`) the publication through lairs' write path. |

## Identity and record keys

Every record is `at://<account>/<collection>/<rkey>`. A Layers rkey is the first
24 hex characters of SHA-256 over `aspect-is-not-fixed|<collection>|<local id>`,
where the local id is stable (a sentence's text, a participant's UUID, and so
on), so a rebuild upserts in place and changing `account` rewrites every
cross-reference consistently. The chive lexicons declare `key: tid`, so chive
records get deterministic, valid TIDs. Each output line is
`{"uri": ..., "value": {...}}`, the value exactly as it is published.

## Pointing into PropBank and VerbNet

The release never copies PropBank or VerbNet. It points at the records the
Layers repository already hosts, by DID-based AT-URI (the lexicons use AT-URI
strings for references; there is no strong-ref field), and pins each target's
CID in `cache/lexical_refs.json`:

- **PropBank rolesets**: `typeDef` records on `ontology.propbank.repo.layers.pub`
  (`did:plc:aowbms64bhay5uiwj2w6wmy2`). Targets: every sense annotation's and
  sense entry's `ontologyTypeRef`, the sense-weight annotations, and the
  distribution entries. All 62 stimulus rolesets resolve.
- **PropBank lemmas**: `resource.entry` records on `resource.propbank.repo.layers.pub`;
  one `same-as` graph edge per verb. All 40 resolve. Each verb's full roleset
  list comes from PropBank's own `instance-of` edges (`graph.propbank`) and is
  listed on the verb entry as knowledgeRefs carrying the AT-URIs.
- **VerbNet**: member `resource.entry` records on `resource.verbnet.repo.layers.pub`
  (131 members for the 40 verbs, one `related-to` edge each, with the class id)
  and class `typeDef` records on `ontology.verbnet.repo.layers.pub` (as
  knowledgeRefs on verb entries, and on sense entries through PropBank's own
  roleset → VerbNet lexlinks).
- **OntoNotes**: 4,451 of the 5,291 rolesets in the distribution exist in the
  PropBank 3.4 frames and point at their typeDef. The other 840 (47 of the 118
  for the 40 verbs, 405 of 6,758 tokens) were retired before PropBank 3.4 and
  carry only a `knowledgeRef` with the OntoNotes roleset id.

In total, 12,673 references reach 4,750 distinct PropBank and VerbNet records,
and `check_metadata.py --live` fetches every one of them from repo.layers.pub
with lairs and confirms its CID.

## Publishing

`scripts/publish.py` publishes through lairs (`WriteOp`, `WriteClient.upload_blob`,
`WriteClient.apply_writes`, lairs' CID function and session store). It is a dry
run unless given `--yes`, and it refuses to run while `release.toml` holds the
placeholder.

Checklist:

1. Create the factslab.io account and note its DID. If it lives on the Layers
   PDS with a factslab.io handle, use the bring-your-own-handle flow
   (`_atproto.<handle>` TXT `did=<did>`), as decomp.io and megaattitude.io do.
2. Set `account = "<did>"` in `release.toml`.
3. Regenerate and check:
   ```bash
   cd metadata
   .venv/bin/python scripts/generate_metadata.py
   .venv/bin/python scripts/check_metadata.py --live
   git add metadata && git commit -m "Set the release account" -- metadata
   ```
4. Log in and review the plan. `--layers-only` leaves out the 50 `pub.chive.*`
   records, so a fresh account gets 22,888 creates:
   ```bash
   LAIRS_APP_PASSWORD='<app password>' .venv/bin/lairs login <handle>
   .venv/bin/python scripts/publish.py --layers-only
   ```
5. Publish the Layers records to the factslab.io account:
   ```bash
   .venv/bin/python scripts/publish.py --layers-only --yes
   ```
6. Verify: `.venv/bin/lairs toc <handle> --counts` matches the table above
   less the two chive collections, and a second
   `scripts/publish.py --layers-only` dry run reports every record `unchanged`.

**Consent scope.** Participants agreed to public release of anonymized data,
so every participant record carries
`consent.scope = "public"` (`CONSENT_SCOPE` in `scripts/generate_metadata.py`),
the lexicon value for public redistribution; `identifiability` stays
`pseudonymous`. The information sheet is at
<http://factslab.io/information_sheet_021523.pdf>.

### The chive submission (the authors' personal account)

The authors will submit the paper to chive from their personal account, not from
factslab.io, so `scripts/publish.py` is run with `--layers-only` and
`chive/submission.jsonl` (1 `pub.chive.eprint.submission`) and
`chive/citations.jsonl` (49 `pub.chive.eprint.citation`) are for the authors to
submit. As generated, they assume the release account, so the following need
to change for a personal-account submission:

- **`submittedBy`** in the submission is the release account's DID; it should
  be the submitting author's DID.
- **The submission's AT-URI** (`at://<release DID>/pub.chive.eprint.submission/3n2rs7ffk22p4`)
  becomes `at://<personal DID>/pub.chive.eprint.submission/<rkey>`, with the
  rkey chive assigns unless the record is written with this one. Each citation's
  `eprintUri` must point at the new URI.
- **The Layers records in `paper.jsonl`** point at the submission: the
  `eprint.eprint` record gives its AT-URI as `eprintIdentifier` and in
  `platformEprintRefs`, and each of the 9 `eprint.dataLink` records gives it as
  `eprintUri` (with the release DID as `eprintDid`). Published as generated,
  these point at a record that does not exist in the release account. Once the
  submission exists, they should be set to its real AT-URI and the submitting author's DID,
  and those 10 records republished. Every other record references the
  `eprint.eprint` record, not the submission, and is unaffected.
- The generator and `check_metadata.py` assume a single account for every
  record ("every record is in the one release account"), so making these edits
  in the generator means adding a separate submitter DID and submission URI to
  `release.toml`. That is not done yet.
- Confirm `publicationStatusSlug` (`preprint`) before submitting. The submission
  embeds `paper/main.pdf` as a blob ref with its CID, so the PDF must be uploaded
  as a blob from the submitting account (`publish.py --layers-only` skips that
  upload).

## Notes on the data

- **Exp 2 senses of bleached sentences are pair-level.** A bleached member's
  `propbank_sense` in `data-similarity.csv` is the sense of the inventory row
  its pair was built from, so 11 of the 106 bleached sentences carry different
  labels in different pairs. The records put these labels on the pair.
- **Participants in two studies.** Four participants appear in two of the
  released studies (one in 1a and 2, three in 1b and 2); see `data/README.md`.
- **Deployed lists.** Lists are recovered from the data: one `stimulus-set` per
  `(condition, list_num)` observed. For Exp 1a these are exactly the deployed
  lists of the three reported conditions, which `materials/src/cloze-items.json`
  holds (built from the inventory's `cloze_list_*` and `cloze_position_*`
  columns). Exp 1b contentful list 1 has no retained participants and therefore
  no node.
- **Unreported inventory columns.** The inventory's generic sentences
  (`sentence_contentful_generic`, `sentence_bleached_generic`) and its Exp 1a
  list and position columns have no records: no released data use the generic
  sentences, and the list each judgment came from is carried by `list_num`.
- **ORCID.** This repository's `CITATION.cff` gives 0000-0003-0057-9246 for the
  first author; the context-sensitivity release's generator uses
  0000-0003-0057-9246. The records use `CITATION.cff`.

## Lexicon and lairs gaps (reported, with the carrier used and a proposed fix)

1. **No list record.** Layers models list *constraints* but not the deployed
   lists. Carrier: one `catalog.collection` (`stimulus-set`) per list with
   `stimulus-for` and `produce` memberships, plus `list_num` on each judgment
   set. Fix: a `judgment.list` record (or `listRef` on `judgmentSet`).
2. **No participant link on a judgment set.** `judgmentSet.agent` is an
   `agentRef` (DID, id, name, knowledgeRef) and cannot point at an
   `acquisition.participant`. Carrier: `agent.id` = `participantId`, the
   participant AT-URI as a feature, and `experimentDef.recordingMethods[].participantRefs`.
   Fix: `participantRef` (at-uri) on `judgmentSet` or `agentRef`.
3. **Multi-slot cloze responses.** A judgment has one `categoricalValue`,
   `scalarValue`, and `freeText`, so a three-dropdown cloze response cannot be
   stored slot by slot in typed fields. Carrier: `categoricalValue` =
   preposition, `freeText` = the full completion, features per slot. Fix:
   `slotResponses: [{slotName, entryRef?, categoricalValue?, scalarValue?}]` on
   `judgment.defs#judgment`.
4. **No model-fit record.** Regression summaries have no home. Carrier:
   `eprint.dataLink` (`dataKind: model-output`) with the parameters as features;
   per-item model outputs as annotation layers, as the bead mapping prescribes.
   Fix: a `judgment.modelFit` record (formula, family, parameters with typed
   decimal summaries, links to experiments).
5. **Online sessions.** `acquisition.session` requires at least one media
   stream, so a browser session with no recording cannot be represented; none
   are emitted.
6. **lairs: `libipld` is unpinned.** lairs 0.9.0 declares `libipld` without an
   upper bound; libipld 4 returns CID objects where lairs expects bytes, so
   `decode_repo_car` silently returns zero records. `requirements.lock` pins
   3.4.1. Fix: `libipld>=3,<4` (or handle `libipld.CID`).
7. **lairs: publish coverage.** `Repository.save` accepts only lairs models (no
   `pub.chive.*`) and re-serializes values; `_fetch_pds_cids` diffs only 26 of
   the 30 Layers collections (not `catalog.*` or `acquisition.*`), so re-publishing
   would re-create those records. `scripts/publish.py` therefore drives lairs'
   writer directly. Fix: include every vendored record NSID in the publish
   registry, and release the raw staging path (`save_many_raw`, unreleased).
8. **lairs model validation is not strict.** The generated models reject
   unknown fields and wrong types but do not enforce `format`, `maxLength`,
   `maxGraphemes`, or integer ranges, which is why the check also runs
   `@atproto/lexicon`.
9. **The PropBank and VerbNet records in the Layers repository are not
   lexicon-valid.** They were published with explicit `null` for absent
   optional fields (for instance `typeKindUri: null`), which the lexicons do not
   declare nullable; strict validation rejects all 200 records sampled from
   each of two accounts. References to them are unaffected. Fix: republish
   from layers-repo with nulls dropped.
